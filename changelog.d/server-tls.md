kind: `alarmant serve` can serve HTTPS from a supplied certificate and key
---
`ALARMANT_TLS_CERT_FILE` and `ALARMANT_TLS_KEY_FILE` (PEM chain, leaf first, and its matching private key; both or neither) make the public listener terminate TLS with `httpant-server`'s rustls acceptor; one alone is refused at start-up, and neither keeps plain HTTP for use behind a proxy. Errors are fixed text and never carry key material. `httpant-server` and `httpant-client` move to 0.7.10 (latest), `httpant-server` with its `tls` feature; `rcgen` 0.14.10 is a dev-dependency for the tests. Verified: 190 Rust tests pass (new: both-or-neither, matching pair, mismatched key refused with no key text, missing files, listener binds with the acceptor), clippy clean, `cargo deny` ok. Not run: a live TLS handshake from a client, and no phone.
