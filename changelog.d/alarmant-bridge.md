kind: `alarmant-bridge` (Synapse human-delivery adapter)
---
A second binary beside `alarmant-pc`: it reads mail for the Synapse role `alarmant` through `synapsed-client` 6.0.0-rc.266, raises one alert on the phone server for each message that passes the gate (`POST /alert`), follows it with `GET /alert/:id`, and on Acknowledge sends the original sender one `[NOTICE] page-acked` mail. The daemon supplies only the authenticated sender, so urgency and the human account are read strictly from the sender's L1 header (`bridge::parse_envelope`; anything else is refused as `malformed`, never echoed). New `bridgeclient` module (https-only key, fixed-shape answers) and, in `bridge`, `parse_envelope`, `utc`, `reply_acked`, `reply_refused`; `OpenAlert` gains `subject` (an older open-alert file still loads). Never re-claims a superseded session. Sends no delivery, fetch, failure or expiry report (constraint 13, S2): a server that is down leaves the message unacked for redelivery. Adds a `synapsed-client` dependency and its lock entries. Verified: `cargo test` (226 unit tests, new ones for the header parser, the clock formatter, the reply forms and the client), clippy `-D warnings`; not run against a live daemon or server.
