# AlarmAnt

An emergency alert that cannot be ignored. A small sender raises a high-priority push; an Android app answers by playing an alarm on the alarm volume stream at maximum, showing a full-screen alert, and repeating until a person taps Acknowledge. If nobody acknowledges in time it escalates to a second person. A daily self-test proves the whole chain still works.

Status: pre-release, not yet run live end to end. This repository holds the sender (server, `alarmant` binary, escalation chain first app, second app, PC alarm), the Windows PC alarm program `alarmant-pc`, the Android app, and the charter, roadmap and patent record (see `ROADMAP.md`). Tests pass in CI (Rust unit tests; Android build, lint, unit and emulator tests), but nothing has been run against a real Firebase project or a real phone yet. The crates.io name `alarmant` is published at 0.0.0 only (checked 2026-11-16).

Enrolling a phone: the app accepts only an `https://` server address (the enrolment code and the ack token must not cross a network in the clear). The server serves HTTPS itself when given `ALARMANT_TLS_CERT_FILE` and `ALARMANT_TLS_KEY_FILE` (a PEM chain and key; use a publicly trusted one, as the phone then uses its system trust store), or sits behind a TLS proxy. On a home LAN with no public certificate, set `ALARMANT_TLS_SELF_SIGNED_NAMES` (the server's IP and/or host name, comma-separated) and, for the client, `ALARMANT_PUBLIC_URL` and the same `ALARMANT_DATA_DIR`: the server makes `tls-cert.pem`, `tls-key.pem` and `tls-names.txt` once, `alarmant enroll` prints a link with the certificate's SHA-256, and the phone accepts only that certificate. Changing the names later is refused until you delete the three files (phones must then enrol again). The PC alarm program trusts the same certificate through `ALARMANT_PC_SERVER_CERT_FILE` (a copy of `tls-cert.pem`). On Windows the data directory is not made owner-only for you: keep it private to the operator. A phone enrolled over `http://` before 0.3.0 must enrol again with an https link. Not yet run on a real phone.

Shared by many portfolio projects (CireSnave, 2026-10-26: "Many of our projects will likely need that"). The Android app needs battery optimisation switched off for that one app; the daily self-test tells us when it stops waking.
